# 🎨 조명이 바뀌어도 믿을 수 있는 색약 보조 카메라 — 팀 프로젝트 제안서

> 💡 **한 줄 요약**
> 기존 색 인식 앱은 "지금 픽셀이 무슨 색인지"만 알려주고, **조명이 바뀌면 같은 물체에도 다른 색 이름을 말한다.** 색약자는 앱이 틀려도 스스로 확인할 방법이 없다. 우리는 **조명을 자동으로 보정해서 조명이 바뀌어도 같은 답을 주고, 확신이 없을 때는 "불확실"이라고 솔직하게 알려주는 색 인식 카메라**를 만든다. 그리고 이걸 **기존 앱과 같은 조건에서 숫자로 비교해서 증명**한다.

---

## 1. 왜 이 주제인가 — 문제 정의

### 1-1. 생각보다 많은 사람이 겪는 문제
- 한국 성인(19~49세) 대상 국민건강영양조사 분석에서 색각이상 유병률은 **남성 5.6%, 여성 0.2%**로 나왔다.
- 남자 약 18명 중 1명꼴이다. 한 강의실에 남학생이 40명이면 2명 정도가 색각이상일 수 있다.
- 대부분 **적록 색약**이라 빨강·초록·갈색·주황 구분이 특히 어렵다.

### 1-2. 색약자가 실제로 막히는 순간
- 옷 고르기: 네이비 vs 검정, 파랑 vs 보라, 카키 vs 갈색
- 음식: 고기가 익었는지(빨강 → 갈색), 과일이 익었는지(초록 → 빨강·노랑)
- 공부·업무: 색으로만 구분된 그래프·지도·노선도, 저항 색띠, 전선 색
- 생활: 충전기·공유기 LED(빨강 = 충전 중, 초록 = 완료)

### 1-3. 진짜 문제는 "틀려도 모른다"는 것
- 일반인은 앱이 이상한 색을 말하면 "어? 아닌데" 하고 알아챈다.
- **색약자는 그 색을 스스로 볼 수 없어서 앱 결과를 그대로 믿을 수밖에 없다.**
- 따라서 색약 보조 앱에서 가장 중요한 성능은 "맞히는 것"만큼이나 **"조건이 바뀌어도 같은 답을 주는 것"**과 **"모를 때 모른다고 말하는 것"**이다.

## 2. 기존 앱들은 어떻게 하고 있나

### 2-1. 대표 앱 조사

| 앱 | 주요 기능 | 조명 대응 방식 | 한계 |
|---|---|---|---|
| **Color Blind Pal** | 카메라로 탭한 지점의 색 이름·HSV·RGB 표시, 색 필터, 붉은 계열에 줄무늬 패턴 오버레이, 색약 시뮬레이션 | **플래시 켜기 버튼** 추가 | 사용자 리뷰에서도 "정확도가 조명에 따라 달라진다", "어두우면 가끔 틀린다"는 언급이 있음 |
| **Color Grab** (다운로드 약 360만) | 실시간 색 측정, 색 이름, 팔레트 생성, 다양한 색 모델 지원 | **화이트밸런스 수동 조절**, 흰색 기준 물체로 **수동 캘리브레이션** 모드 | 보정을 **사용자가 직접** 해야 함. 색약자가 "이 물체가 진짜 흰색인지"를 판단해야 하는 모순 |
| **Color Identifier 류 앱들** | 사진에서 색 탭하면 이름 표시 | 개발사가 **플래시 토글**을 추가해 대응 | 스토어 리뷰에 "조명과 상관없이 색이 부정확하다", "색이 완전히 다르다"는 불만이 반복됨 |

### 2-2. 조사하면서 발견한 공통점
1. **조명 대응이 "플래시를 켜라" 또는 "직접 보정해라" 수준에 머물러 있다.** 플래시는 거리·반사에 따라 오히려 색을 날려버리기도 하고, 수동 보정은 색약자에게 부담이다.
2. **조명별로 정확도가 얼마나 되는지 공개한 앱을 찾지 못했다.** "정확하다"는 주장은 있지만 근거 숫자가 없다.
3. **결과를 얼마나 믿어도 되는지 알려주는 기능을 찾지 못했다.** 확신이 낮을 때도 똑같이 단정적으로 색 이름을 말한다.
4. **대부분 "픽셀 한 점"의 색을 읽는다.** 그림자나 반사광이 걸린 점을 찍으면 그대로 틀린다.

> ⚠️ 위 2~4번은 "우리가 찾아본 범위에서"다. 발표 전에 팀원들이 한 번 더 앱을 직접 설치해서 확인하자. 이 확인 과정 자체가 "기존 앱 비교 실험" 데이터가 된다.

## 3. 우리 프로젝트의 차별점

### ✅ 차별점 1. 자동 조명 보정 — 사용자는 아무것도 안 해도 된다
- 전통적인 color constancy 알고리즘(Gray World, White Patch)과 **기준 카드 기반 보정**을 구현하고 비교한다.
  - **Gray World**: 장면 전체의 평균 반사율은 무채색(회색)이라고 가정하고, 채널별 평균이 같아지도록 보정
  - **White Patch**: 장면에서 가장 밝은 부분을 흰색이라고 가정하고 그 색을 기준으로 보정
  - **기준 카드**: 알고 있는 색이 인쇄된 작은 카드를 같이 찍으면, 카드를 자동으로 찾아서 정확하게 보정 (가장 정확, 선택 기능)
- Color Grab처럼 사용자가 "흰색을 찍어주세요"를 할 필요가 없다.

### ✅ 차별점 2. "조명이 바뀌어도 같은 답" 을 숫자로 증명한다
- 같은 색 샘플을 **여러 조명에서 찍고**, 우리 시스템과 기존 앱이 **같은 이름을 얼마나 일관되게 말하는지** 측정한다.
- 기존 앱은 주장만 있고 숫자가 없다. 우리는 **"조명별 정확도"와 "조명 간 일관성"**을 표로 보여준다. → 이게 발표에서 가장 강력한 한 장이 된다.

### ✅ 차별점 3. 모를 때는 "불확실"이라고 말한다
- 예시 출력:
  - `빨강 (확신 높음)`
  - `갈색 또는 주황 (불확실 — 더 밝은 곳에서 다시 찍어보세요)`
- 색약자에게 **틀린 확답보다 솔직한 "모르겠다"가 훨씬 안전하다.** 기존 앱과 가장 직관적으로 다른 부분이다.

### ✅ 차별점 4. 픽셀이 아니라 "물체"의 색을 읽는다
- 한 점이 아니라 물체 영역 전체에서 그림자·반사 하이라이트를 제외하고 대표 색을 계산한다.
- 딥러닝 단계에서는 YOLO로 물체(옷, 과일, 컵 등)를 찾고 **"물체 이름 + 색"**으로 알려준다. 예: `티셔츠: 네이비`

## 4. 배경 지식 — 왜 조명이 바뀌면 색 이름이 틀리나

카메라는 물체의 색이 아니라 **물체에 반사되어 들어온 빛**을 찍는다.

> 📐 **핵심 공식**
> 찍힌 색 ≈ 물체 고유의 색(반사율) × 조명의 색

같은 흰 종이도 조명에 따라 픽셀 값이 달라진다.

| 조명 | 흰 종이의 대략적인 RGB | 단순 색 이름 앱의 답 |
|---|---|---|
| 창가 햇빛 (약간 푸름) | (235, 240, 255) | 연한 하늘색 |
| 전구색 조명 (노랑) | (255, 215, 165) | 베이지 / 살구색 |
| 어두운 방 | (90, 90, 90) | 회색 |

사람은 뇌가 조명을 자동으로 빼고 인식하기 때문에(**color constancy, 색 항상성**) 셋 다 흰 종이로 본다. 카메라의 자동 화이트밸런스도 이걸 흉내 내지만 완벽하지 않다. 2015년 "파검/흰금 드레스" 논란이 같은 원리다.

특히 **갈색은 "어두운 주황"**이라 밝기만 조금 바뀌어도 이름이 넘어간다. 색약자가 가장 헷갈리는 조합(갈색/주황, 빨강/갈색)이 앱도 가장 잘 틀리는 조합이라는 점이 이 주제의 핵심이다.

## 5. 시스템 구조

```
카메라 영상 입력
   ↓
[전처리] 노이즈 제거, 과노출(반사) 영역 마스킹
   ↓
[조명 추정·보정] Gray World / White Patch / 기준 카드(선택)
   ↓
[물체 영역 찾기] 윤곽선 기반 영역 분리  →  (딥러닝 단계) YOLO 물체 검출
   ↓
[대표 색 계산] 영역 내 그림자·하이라이트 제외 후 대표 색
   ↓
[색 이름 분류] HSV/Lab 규칙  vs  CNN  vs  전이학습
   ↓
[신뢰도 판단] 경계 근처 색이면 "불확실" 표시
   ↓
[영상 안정화] 여러 프레임 결과를 투표로 합쳐 깜빡임 방지
   ↓
출력: "티셔츠: 네이비 (확신 높음)"
```

## 6. 수업 내용을 이렇게 전부 쓴다 (2~13주차)

| 주차 | 수업 내용 | 프로젝트에서 쓰는 곳 |
|---|---|---|
| 2 | 픽셀, 채널, 색공간 변환 | RGB → HSV/Lab 변환, 색상(Hue)과 밝기 분리, 색 이름 규칙의 기반 |
| 3 | 밝기·대비, 히스토그램 | 채널별 평균·최댓값으로 Gray World / White Patch 조명 추정, 밝기 보정 |
| 4 | 공간 필터링, 블러 | 노이즈 억제, 영역 평균 색을 안정적으로 계산 |
| 5 | 이진화, 형태학 연산 | 과노출(반사 하이라이트)·그림자 영역을 마스크로 제거, 물체 영역 정리 |
| 6 | 에지, 윤곽선, 도형 검출 | 물체 영역 분리, 기준 카드의 사각형 테두리 검출 |
| 7 | 코너, ORB 특징점 매칭 | 기준 카드 템플릿과 매칭해 카드 자동 인식 |
| 9 | 영상 정합, homography | 비스듬히 찍힌 기준 카드를 반듯하게 펴서 색 패치 위치 정확히 읽기 |
| 10 | 비디오, 움직임 검출 | 프레임 간 결과 투표로 안정화, 조명이 급변하는 순간 감지 |
| 11 | CNN 기초 | 색 패치 → 색 이름 분류 (규칙 기반과 비교) |
| 12 | 전이학습 | 사전학습 모델로 조명 변화에 강한 색 분류기 학습 |
| 13 | YOLO 객체 탐지 | 물체를 찾아 "물체 이름 + 색"으로 안내 |

> 💡 모든 기법이 **"왜 필요한지" 이유가 있는 자리**에 들어간다. 억지로 끼워 넣은 기법이 없다는 점이 기술 적용 점수(6점)에서 강점이다.

## 7. 데이터 계획

### 7-1. 직접 촬영 (메인)
- **색 샘플**: 색종이·페인트 칩·단색 옷 등 정답 색을 아는 물체 약 30개
- **색 이름 클래스**: 일상에서 쓰는 기본 색 11개 (검정, 흰색, 회색, 빨강, 주황, 노랑, 초록, 파랑, 보라, 분홍, 갈색) + 필요하면 네이비·카키 등 추가
- **조명 조건 6종**: 햇빛(창가), 그늘, 형광등, 전구색 LED, 주광색 LED, 휴대폰 플래시
- **규모 예시**: 30개 × 6조명 × 각도 5장 = **약 900장**, 팀원 5명이 나눠 찍으면 하루면 가능
- 장점: **정답이 확실**하고, **조명 조건을 우리가 통제**할 수 있어서 비교 실험이 깔끔하다.

### 7-2. 공개 데이터 (보조)
- 조명 보정 알고리즘 검증용으로 **ColorChecker 데이터셋**(Color constancy 연구에서 표준으로 쓰는 데이터, 사진마다 컬러 체커 카드가 찍혀 있음) 활용 가능
- 물체 검출은 COCO 사전학습 YOLO 모델을 그대로 사용 (옷, 컵, 과일 등 이미 포함)

### 7-3. 라벨링
- 촬영할 때 파일명에 `물체번호_정답색_조명_번호.jpg`로 저장하면 **라벨링이 자동으로 끝난다.**

## 8. 평가 계획 — 이렇게 증명한다

### 8-1. 비교 대상 (baseline)
1. 보정 없음 (단순 HSV 규칙) ← 기존 앱과 비슷한 수준
2. Gray World 보정
3. White Patch 보정
4. 기준 카드 보정
5. CNN / 전이학습 분류기
6. **기존 앱 (Color Blind Pal 등)** — 같은 물체·같은 조명에서 직접 찍어 결과 기록

### 8-2. 평가 지표
| 지표 | 의미 | 왜 중요한가 |
|---|---|---|
| 조명별 정확도 | 조명마다 색 이름을 맞힌 비율 | 어떤 조명에서 약한지 파악 |
| **조명 간 일관성** | 같은 물체가 6개 조명에서 모두 같은 이름으로 나온 비율 | **이 프로젝트의 핵심 지표** |
| 혼동 행렬 (confusion matrix) | 어떤 색끼리 헷갈리는지 | 갈색/주황, 파랑/보라 같은 약점 분석 |
| 불확실 표시의 정직성 | "불확실"이라고 한 것 중 실제로 틀렸을 비율, "확신 높음" 중 맞은 비율 | 신뢰도 기능이 진짜 의미 있는지 검증 |

### 8-3. 발표에서 보여줄 핵심 그래프 (예상)
- x축: 조명 6종 / y축: 정확도 / 선: 보정 없음 vs Gray World vs 기준 카드 vs CNN vs 기존 앱
- "보정 없음과 기존 앱은 전구색 조명에서 크게 떨어지는데, 우리 방법은 유지된다"를 한 장으로 보여주는 것이 목표

## 9. 시연 시나리오 (15주차)

1. 같은 베이지색 옷을 **형광등 → 전구색 조명 → 창가** 순서로 옮기며 비춘다.
2. 화면 왼쪽: 보정 없는 결과 (베이지 → 주황 → 회색으로 바뀜)
3. 화면 오른쪽: 우리 시스템 결과 (계속 베이지 유지)
4. 갈색/주황 경계의 물체를 어두운 곳에 두면 → `갈색 또는 주황 (불확실)` 표시
5. 여러 물체를 한 화면에 두면 YOLO가 각각 찾아서 `컵: 빨강`, `사과: 초록`처럼 안내

> 💡 조명만 바꾸면 되는 시연이라 **강의실에서 그대로 재현 가능**하다. 전구색 LED 스탠드 하나면 충분하다.

| 2~3 | 기존 앱 조사·직접 설치 테스트, 색 샘플·조명 준비 | 기존 앱 비교 메모 |
| 4 | 주제·역할 확정, 촬영 규칙 정하기 | 역할표, 촬영 가이드 |
| 5~6 | 데이터 촬영, HSV 규칙 기반 색 이름 분류 + 보정 없음 baseline | baseline 정확도 |
| 7 | Gray World / White Patch 구현, 반사·그림자 마스크 | 보정 전후 비교 |
| 8 | **중간점검**: 조명 보정 + 색 이름 프로토타입 시연 | 기획서, 초기 결과 |
| 9 | 기준 카드 검출 (ORB + homography) | 카드 보정 결과 |
| 10 | 실시간 영상, 프레임 투표 안정화 | 영상 데모 |
| 11~12 | CNN / 전이학습 색 분류기 학습, 신뢰도 기능 | 모델 성능 비교 |
| 13 | YOLO 물체 검출 연동 | "물체 + 색" 출력 |
| 14 | 전체 통합, 기존 앱 비교 실험, 오류 분석 | 최종 비교표·그래프 |
| 15 | 발표·시연, 보고서·코드 제출 | 최종 결과물 |

> 💡 **8주차 중간점검 시점에 이미 "조명 보정 전후 비교"라는 완결된 결과가 나온다.** 이후 기능은 그 위에 하나씩 쌓는 구조라, 뒤에서 막혀도 결과물이 없어지는 위험이 적다.

## 12. 예상 질문과 답변 (FAQ)

**Q. 색 인식 앱은 이미 엄청 많은데 의미가 있나?**
A. 기존 앱은 "색 이름을 알려준다"에서 멈춰 있다. 우리는 **조명이 바뀌어도 믿을 수 있는지**를 해결하고 **숫자로 증명**한다. 같은 주제라도 해결하는 문제가 다르다.

**Q. Color Grab에 화이트밸런스 기능이 이미 있지 않나?**
A. 있다. 하지만 **사용자가 직접 흰색 물체를 찍어 보정해야 한다.** 색약자가 "이게 진짜 흰색인지" 판단해야 하는 모순이 있다. 우리는 **자동**으로 하고, 여러 보정 방법을 **비교해서 어떤 게 나은지까지 보여준다.**

**Q. 너무 쉬운 주제 아닌가? 색 이름만 맞히면 되는 거잖아.**
A. 단순히 맞히는 건 쉽지만 **"조명이 바뀌어도 맞히는 것"은 컴퓨터 비전에서 아직 연구가 이어지는 문제(color constancy)**다. 그리고 수업 2~13주차 기법이 전부 들어간다. 난이도는 충분하다.

**Q. 딥러닝은 어디에 쓰나?**
A. 11~12주차: 색 패치 분류를 CNN·전이학습으로 해서 규칙 기반과 비교한다. 13주차: YOLO로 물체를 찾아 "물체 + 색"으로 안내한다.

**Q. 데이터는 어떻게 구하나?**
A. 직접 찍는다. 정답을 아는 색 샘플을 조명만 바꿔 찍으면 되고, 파일명으로 라벨링이 자동이다. 공개 데이터는 보조로 쓴다.

**Q. 평가를 어떻게 객관적으로 하나?**
A. 정답이 명확하다 (색 샘플의 실제 색). 조명별 정확도, 조명 간 일관성, 혼동 행렬, 기존 앱 대비 비교까지 전부 수치로 나온다.

**Q. 망하면 어떡하나?**
A. 가장 기본인 "보정 없음 vs Gray World 비교"만 해도 완결된 결과가 나온다. 나머지(기준 카드, CNN, YOLO)는 **단계적으로 추가**하는 구조라 어디서 멈춰도 발표할 결과가 있다.

## 13. 위험 요소와 대응

| 위험 | 대응 |
|---|---|
| 색 이름의 정답이 애매함 (이게 주황이야 갈색이야?) | 촬영 전에 팀원 전원이 합의한 정답만 사용, 애매한 샘플은 "경계 샘플"로 따로 분류해 신뢰도 기능 평가에 활용 |
| 휴대폰 카메라 자동 보정이 실험을 방해 | 가능하면 화이트밸런스·노출 고정 촬영(프로 모드), 안 되면 같은 기기로 통일 |
| 기준 카드 인쇄 색이 부정확 | 카드는 "상대적 기준"으로만 사용, 정밀 보정은 공개 ColorChecker 데이터로 검증 |
| Gray World가 한 가지 색이 가득한 장면에서 실패 | 이것 자체가 분석 거리. 실패 사례를 보여주고 White Patch·카드 방식과 비교 |
| 기존 앱 비교가 공정하지 않다는 지적 | 같은 기기·같은 위치·같은 조명에서 찍고, 조건을 보고서에 전부 기록 |

## 14. 교수님 평가 기준과의 대응

| ② 데이터 구성 (3) | 직접 촬영, 정답 확실, 조명 조건 통제, 출처 명확 |

| ④ 구현 완성도 (7) | 8주차에 핵심 기능 완성 → 이후 단계적 확장이라 안정적 |
| ⑤ 성능평가·개선 (4) | 보정 방법별·조명별 비교, 기존 앱 대비 비교, 오류 분석 |
